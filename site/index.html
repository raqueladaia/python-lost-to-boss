Environments III: Tell VSC to use your environment

Tell VSC to use your environment

The terminal and VSC’s Run button are two different things. Activating the environment in the terminal is not enough: you also have to tell VSC which Python to use.

  1. Press Ctrl + Shift + P (macOS: Cmd + Shift + P).
  2. Type Python: Select Interpreter and press Enter.
  3. Choose the one that has env in its path (often marked “Recommended”).

Libraries: And similar elements

And similar elements

Library. Collection of modules and packages that provide a set of related functionalities. E.g. numpy, pandas, scipy

Module. Single code file that executes simple functions. E.g. os, glob, math

Package. Directory (=folder) that organizes modules. Usually contains an __init__.py file, which marks the folder as a package and runs when you import it.

import numpy as np   # import a library and give it a short name
import os            # import a module

How to execute a script: Run vs. Debug with Breakpoints

Run vs. Debug with Breakpoints

Run. Executes every line in your script without a break.

Debug. Allows you to pause execution of a script at the lines where you set a Breakpoint.

Inspect your code, variables, functions…; test lines of code; fix issues; quickly visualize your data…

Breakpoint. A marker you set on your script to stop execution. Click to the left of a line number to set one (a red dot appears). Breakpoints next to comments or empty lines will not work.

Run and Debug in VSC: Where to click

Where to click

▶ Run Python File
The play button at the top right of the editor runs the whole script. The results appear in the terminal.
▶ ▾ Python Debugger: Debug Python File
The little arrow next to the play button. The script stops at your first breakpoint. (Or press F5 and choose Python Debugger › Python File. On a Mac you may need Fn + F5.)
Variables panel
While the script is paused, the left panel shows every variable and its value.
F10 step over
Runs the next line only, so you can watch each variable change.
F5 continue · Shift+F5 stop
Continue to the next breakpoint, or stop debugging.
Debug Console
While paused, type any variable name or line of code there and press Enter to try it out.
If any line has a syntax error (for example an unfinished x =), Python refuses to run the whole file, even the lines before your breakpoint. Comment out the lines you have not finished yet: select them and press Ctrl + / (macOS: Cmd + /).

Interpret the results.

Then make the groups differ on purpose and see how the statistics react.

The analysis is already written, commented out, at the bottom of part_4_challenges.py. Uncomment it once, run the whole script, and read the table. Then work through TODO #1 to #4.

Need a hint?
In the ANOVA table, the PR(>F) column holds the p-values for sex, experimental condition and their interaction (ignore the Intercept row). Below 0.05 usually means a significant effect. The weights are random numbers around 30 g, so at first you should usually find no effect (each row still has a 5% chance of a false positive). Only if the interaction is significant, look at the follow-up t-tests, which compare exp vs ctrl within each sex; otherwise the main effects in the table answer the question. The EXPERIMENT block (TODO #1 to #3) changes the weights before the statistics run, so re-running the script shows how the table changes. TODO #4, at the very end, adds the t-test for the females.

# Time to figure out if your treatment has worked!
# We are going to perform a 2-way ANOVA because we have two independent variables
# These independent variables are: sex and experimental_condition
# and we will also assess their interaction
# Our dependent variable is the weight of the mice

# We need to import the libraries that will help us with the ANOVA and the post-hoc tests
from statsmodels.formula.api import ols
from statsmodels.stats.anova import anova_lm
from scipy import stats

# EXPERIMENT: make the groups differ (uncomment ONE option, re-run the whole script and see how the statistics change)
# Our weights are random numbers around 30 g, so without any change the groups should NOT differ.
# lambda x: ... is a tiny one-line function; with axis=1, apply() runs it on each ROW, so x is one mouse
# "a if condition else b" is a one-line if/else (you will learn if/else in Part 6)
# np.random.binomial(1, p, 1)[0] is 1 with probability p, and 0 otherwise (like flipping a coin)

# TODO #1: Uncomment OPTION A, re-run the whole script and investigate the changes in the data.
# Have the statistics changed?
# OPTION A: exp mice gain 16% of their weight (with probability 0.55),
# ctrl mice lose 5% of their weight (with probability 0.45)
df['weight'] = df.apply(lambda x:
                        x['weight'] + x['weight'] * (0.16 * np.random.binomial(1, 0.55, 1)[0])
                        if x['experimental_condition'] == 'exp'
                        else x['weight'] - x['weight'] * (0.05 * np.random.binomial(1, 0.45, 1)[0]),
                        axis=1)  # axis=1: the function is applied to each ROW (each mouse)

# OPTION B: create differences between sexes AND experimental conditions.
# The probability of the weight change is given by this dictionary:
# probs = {'M': 0.9,
#          'F': 0.1,
#          'ctrl': 0.45,
#          'exp': 0.55}
# # First change the weight based on the experimental condition
# df['weight'] = df.apply(lambda x:
#                         x['weight'] + x['weight'] * (0.16 * np.random.binomial(1, probs[x['experimental_condition']], 1)[0])
#                         if x['experimental_condition'] == 'exp'
#                         else x['weight'] - x['weight'] * (0.05 * np.random.binomial(1, probs[x['experimental_condition']], 1)[0]),
#                         axis=1)
# # TODO #2: Proceed changing the weight based on the sex
# # Every mouse gains 10% of its weight, with the probability of its sex
# df['weight'] = df.apply(lambda x:
#                         x['weight'] + x['weight'] * (0.10 * np.random.binomial(1, probs[x['sex']], 1)[0]),
#                         axis=1)
# # TODO #3: Change the probabilities in the dictionary (e.g. 'M': 0.6, 'F': 0.3) and re-run the script
# # a few times. What happens to the statistics?
# # Hint: smaller differences between the groups are often missed: with ~50 mice, the test does not have
# # enough statistical power to detect them every time.

# First, the independent variables have to be categorical
df['sex'] = df['sex'].astype('category')
df['experimental_condition'] = df['experimental_condition'].astype('category')

# Fit the model
# C(variable, Sum) treats the variable as categorical with "Sum" coding, which a Type III ANOVA needs
# to give correct p-values. The "*" means: sex + experimental_condition + their interaction (sex:experimental_condition)
model = ols('weight ~ C(sex, Sum) * C(experimental_condition, Sum)', data=df).fit()

# Perform the ANOVA
# Type III (with Sum coding) tests each effect adjusted for all the others, including the interaction.
# In a balanced design Type II and Type III give the same result; Type II is preferred when there is no interaction.
anova_results = anova_lm(model, typ=3)  # typ=3 specifies Type III sums of squares

print(anova_results.to_string())  # .to_string() prints the whole table (without hiding columns behind "...")

# How to read the table:
# - There is one row per effect: sex, experimental_condition and their interaction (the row with ":")
# - The PR(>F) column contains the p-values: the effect is significant if p < 0.05
# - The Intercept row can be ignored (it only tests if the average weight is different from 0, which we know!)
# - Residual is the variability that the model cannot explain

# Read the p-value of the interaction directly from the table: .loc[row, column]
p_interaction = anova_results.loc['C(sex, Sum):C(experimental_condition, Sum)', 'PR(>F)']
print(f"Interaction p-value: {p_interaction:.2g} -> " + ("look at the follow-up t-tests below" if p_interaction < 0.05 else "not significant: the main effects in the table answer the question; the t-tests below are only an example"))

# Post-hoc tests
# Only look at these tests if the interaction row of the ANOVA has p < 0.05.
# If there is no interaction, the main effect of experimental_condition in the ANOVA already answers the question.
# A significant interaction means that the treatment works differently in males and females.
# Then we ask "has the treatment worked?" in each sex separately: exp vs ctrl within the males,
# and exp vs ctrl within the females (simple effects of the treatment), with t-tests.
# We correct for the 2 tests (Bonferroni: significant if p < 0.05 / 2).
alpha_corrected = 0.05 / 2

# Let's start with the males
males = df.query('sex == "M"')
males_exp_weight = males.query('experimental_condition == "exp"')['weight']
males_ctrl_weight = males.query('experimental_condition == "ctrl"')['weight']

# equal_var=False runs Welch's t-test, which does not assume that both groups have the same variance
t_statistic, p_value = stats.ttest_ind(males_exp_weight, males_ctrl_weight, equal_var=False)
print("Males, exp vs ctrl:")
print(f"t-statistic: {t_statistic:.4f}")
print(f"p-value: {p_value:.2g}")
print(f"Significant after Bonferroni correction? {p_value < alpha_corrected}")

# TODO #4: Do the same for the females
females = df.query('sex == "F"')
females_exp_weight = females.query('experimental_condition == "exp"')['weight']
females_ctrl_weight = females.query('experimental_condition == "ctrl"')['weight']

t_statistic, p_value = stats.ttest_ind(females_exp_weight, females_ctrl_weight, equal_var=False)
print("Females, exp vs ctrl:")
print(f"t-statistic: {t_statistic:.4f}")
print(f"p-value: {p_value:.2g}")
print(f"Significant after Bonferroni correction? {p_value < alpha_corrected}")

Flow control: What is it?

What is it?

Control of the order and execution of instructions.

Why is it important?

Decision Making. Enables programs to make decisions based on conditions. If, elif, else

Repetition. Allows repetitive execution of code blocks without code duplication. For, while

Efficiency. Improves program efficiency by controlling which code blocks are executed. If/elif/else

Readability. Enhances code readability and maintainability by providing a structure.

If, elif, else: I have conditions

I have conditions

Control flow tools that allow you to execute specific blocks of code if a given condition is True.

If. If the condition after if is True, execute the code that follows.

Elif. Short for “else if”. Checked only if the conditions before it were False.

Else. If no condition was True before, execute the instruction following else.

x = 10
y = 100
if x < y:
    print(f'{x} is less than {y}')
elif x == y:
    print(f'{x} is equal to {y}')
else:
    print(f'{x} is larger than {y}')

The indentation (4 spaces) tells Python which lines belong to each block.

Over and over and over again

Allows you to execute a block of code repeatedly for a fixed number of times or over a sequence of items.

for i in [1, 2, 3, 4]:

While loops: While it lasts…

While it lasts…

  • Allows code to be executed repeatedly based on a given Boolean condition.
  • The loop continues to execute as long as the condition remains True.
  • Used when the number of iterations is not known beforehand.
  • Depends on dynamic conditions during runtime.

while i < 10:
    print(f'Inside while loop - Iteration {i}')

Environments: What, why and how

What, why and how

What is an environment?

A folder within your repository folder that contains subfolders and documents that allow you to use libraries. Usually it is named env, venv or .venv.

Why do you want one?

To make sure that the versions of a library that you may have in two different projects do not have compatibility issues.

How do you know you have created one?

Go to your repository folder. Is there an env folder in it? If so, you have created an environment.

Create it

  1. Create the folder “Repositories” in your “Documents” folder.
  2. In “Repositories”, create a folder with the name of your project (e.g. “lost_to_boss”). This is your repository.
  3. Open VSC → Explorer → Open Folder → select your repository folder.
  4. Open a new terminal (Terminal › New Terminal) and check the folder path is your repository. On Windows it looks like C:\Users\your_name\Documents\Repositories\lost_to_boss
Windows
python -m venv env
.\env\Scripts\activate
macOS
python3 -m venv env
source env/bin/activate

When it is active, the terminal line starts with (env). To leave the environment, type deactivate. Then tell VSC to use it: Select Interpreter.

Troubleshooting: Errors when activating an environment

Errors when activating an environment

  1. Windows: “running scripts is disabled on this system”? Type this in the terminal, answer Y, and activate again:
    Windows terminal
    Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
  2. “Python was not found” or “python is not recognized”? Python was installed without “Add python.exe to PATH”. Run the Windows installer (64-bit) again, choose Modify, click Next, and on Advanced Options tick “Add Python to environment variables” (or uninstall and reinstall, ticking “Add python.exe to PATH” on the first screen). Then close and reopen VSC.
  3. Do you have the correct folder opened? Check “Explorer” in the left menu. If “NO FOLDER OPENED” is displayed, click on “Open Folder” and select your folder.
  4. Are you in the right folder path? Type pwd in the terminal. If it points to “Documents”, type cd Repositories/lost_to_boss. If you are inside the environment folder, go one folder up with cd ..
  5. Still lost? Close VSC, reopen it, click “Open Folder” in Explorer and select your folder.

Stuck?: The most common errors and how to fix them

The most common errors and how to fix them

When Python stops with an error, read the last line of the message first: it names the error. The lines above it show the file and the line number where it happened.

ModuleNotFoundError
VSC is not using your environment (Select Interpreter), or the library is not installed (pip install it with the environment active).
SyntaxError
Python cannot read a line: an unfinished x =, a missing bracket or quote, or curly quotes “ ” instead of straight quotes ". Python refuses to run the whole file until it is fixed.
IndentationError
The spaces at the start of a line are wrong. Code inside if, for and while blocks is indented by 4 spaces; everything else starts at the left edge.
NameError
You use a variable or a library before creating or importing it, or you misspelled it (Python is case sensitive). Did you run the lines above it?
FileNotFoundError
Python cannot find a file. Check that VSC has your repository open and that the file is where the path says (e.g. example_data/data.xlsx).
KeyError
A dictionary key or a DataFrame column name does not exist. Check the spelling, e.g. with df.columns.
IndexError
You ask for a position that does not exist. Remember that Python starts counting at 0, so the last of 8 elements is index 7.
No figure appears
Figures open when the script reaches plt.show(). If no window opens, uncomment the 2 lines import matplotlib and matplotlib.use('TkAgg') near the top of the script (leave plt.ion() commented unless you want to see figures while debugging).

Still stuck? Copy the last line of the error into a search engine: someone has had the same problem before.

Install and check

What is a library?

A set of folders, subfolders and scripts that have functionalities. E.g. matplotlib lets you plot your data and numpy lets you perform computations.

How do you use one?

You import it in your script: import numpy as np

How do you install one?

Libraries live on the internet. Activate your environment, then:

pip install name_of_library
